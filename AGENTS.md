# Working on OpenGeo Studio

Read README.md, ROADMAP.md and CONTRIBUTING.md, then the affected component.
Finish Studio startup, Catalog inspection, Project save/reopen and publication
before expanding unused integrations. Keep local implementation, connected
acceptance and production deployment claims separate.

Preserve persistent resource identities, source custody, data, authorization,
upstream notices and contribution credits. Collections and geographic tags never
grant access to member resources. Inspection never uploads or copies data.

Use OpenGeo Studio for the application and OpenGeo.Tools for the umbrella brand
and public methods library. Describe Studio as an open workspace for geospatial
analysis and publishing. Describe the community edition as the full
suite of tools, with implementation and acceptance status recorded honestly.
Keep the complete core workflow and security fixes in the community edition.
Public materials describe the software, contribution process, deployed examples
and available fee-based hosting and enterprise support services. These services
support the same software; do not invent a separate feature tier, prices, service
commitments or publish internal business research.

Write public documentation in a professional, concise voice. Lead with what
readers can accomplish; keep audit narration, capture notes and editorial dates
out of product introductions. State release limits plainly in the appropriate
status guide. Separate executable operations, metadata imports and retained
definitions; source inclusion is not connected acceptance. Check links in the
standalone export layout. Include images only when they are clear, polished and
useful; otherwise omit them. Retain data terms and substantive source dates.
Describe low cost as a design goal until a measured workload supports it.

Use existing runners, lockfiles and focused checks. Keep `.opengeo/`, credentials,
private datasets, dependency directories and build outputs outside Git. The local
synthetic-authentication mode is loopback-only and must never become a production
sign-in path. Do not perform paid/cloud work or deployment without scoped authority.
