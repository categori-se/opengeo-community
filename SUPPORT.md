# OpenGeo Studio support

## Community help

Use [GitHub Issues](https://github.com/categori-se/opengeo-community/issues) for
installation questions, reproducible bugs, documentation improvements and feature
requests. Community support is provided as maintainer and contributor time allows.

For deployment help, include your source commit, operating system, Node/Python/
Podman versions, deployment step, AWS region and a short redacted error. Describe
what you expected and what happened. Include a minimal example dataset when its
license and privacy terms permit sharing.

Keep passwords, access tokens, private keys, AWS credentials, database exports,
private datasets and browser authentication state out of issues and pull requests.
Report security vulnerabilities through [SECURITY.md](SECURITY.md).

Start with the [local guide](docs/community-development.md),
[AWS deployment guide](docs/community-aws.md),
[deployment choices](docs/community-deployments.md),
[workflow guide](docs/community-workflow.md),
[capability and maturity matrix](docs/community-capabilities.md),
[reference comparisons](docs/reference-applications.md) and [roadmap](ROADMAP.md).
When reporting a problem, say whether you used the demo, a local installation or
hosted Studio.

## Hosting and enterprise support

We offer hosting and enterprise support as fee-based services for OpenGeo Studio.
The community edition provides the full suite of tools; these services help
organizations deploy and operate the same software.

| Service | Scope to agree |
| --- | --- |
| Hosted Studio access | Use an installation we operate, with account and resource permissions and agreed services. Existing users can [open Studio](https://studio.opengeo.tools/); new users can [request hosted Studio access](mailto:2301690+aaronkyle@users.noreply.github.com?subject=OpenGeo%20Studio%20access). |
| Assisted company deployment | Installation, configuration, private connections, integrations, training and handover into an organizational environment. |
| Managed organizational deployment | Agreed operation of an organizational installation, including the maintenance, upgrades, backup/recovery and support responsibilities selected for that engagement. |

Describe the recurring work you need to finish: save and reopen a study, reuse
shared data, deliver an output or hand a project to a colleague. Identify the
deployment operator, account administrators, data location and publishing
destinations. Agree covered workflows, retention, recovery objectives, update
approval and support hours, with usage limits based on expected storage,
processing and delivery. The [deployment guide](docs/community-deployments.md)
compares these choices and identifies current installation acceptance limits.

An inquiry does not activate a subscription or grant access. The software license
does not establish a hosting entitlement or service guarantee.

For hosting or enterprise support inquiries, contact
[Aaron Kyle Dennis](mailto:2301690+aaronkyle@users.noreply.github.com). Describe your intended workflows,
hosting needs and support requirements so we can discuss scope, terms and
availability. Pricing and service commitments are agreed for the engagement.
